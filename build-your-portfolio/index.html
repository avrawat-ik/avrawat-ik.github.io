Part 1 · 45 to 60 minutes · The most important step

Set up VS Code, GitHub and your coding assistant

One app, two accounts and an assistant, set up from scratch. No experience assumed: if you've never opened VS Code or GitHub, start at 1A. Already have something? Skip that step, but do the three tests at the end.

Why this step matters most

Common problems start here: an assistant on a free plan that runs out partway, a chat mode that can't touch files, or the browser chat instead of the editor. Once your assistant passes the three tests at the end of this part, it can install tools, download the project, run it and fix most errors for you.

1A · Install VS Code

VS Code is a free app from Microsoft for working on code. You'll build your whole site inside it.

  1. Go to code.visualstudio.com/download and click the Mac download.
  2. Open your Downloads folder and double-click the file you just downloaded.
  3. Drag Visual Studio Code into your Applications folder.
  4. Open it from Applications (or press Cmd+Space, type Visual Studio Code and press Enter). If your Mac warns that it was downloaded from the internet, click Open.
  5. Optional: to keep it in the Dock, Control-click its icon in the Dock and choose Options → Keep in Dock.
  6. Recommended: press Cmd+Shift+P, type shell command, and choose Shell Command: Install 'code' command in PATH (it may also mention Copilot; choose No to that part). This lets the terminal open folders in VS Code.

Guide: VS Code on macOS

  1. Go to code.visualstudio.com/download and click the Windows download (the User Installer is the right one; it doesn't need administrator rights).
  2. Open your Downloads folder and double-click the installer (VSCodeUserSetup…exe).
  3. Accept the agreement and keep the default options. The installer adds VS Code to your PATH, so the terminal can open it. If it offers Add "Open with Code" action, tick it.
  4. If it asks about GitHub Copilot CLI, choose not to add it; you don't need it for this guide.
  5. Click Finish with Launch Visual Studio Code ticked.

Guide: VS Code on Windows

VS Code opens on a Welcome page. You can close it.

1C · Create a GitHub account

GitHub stores your code online and hosts your published site. It's free.

  1. Go to github.com/signup. Enter your email, a password and a username, or choose Continue with Google.
  2. Pick your username with care: it appears in your links, for example your-username.github.io. Your name, like jane-doe, works well.
  3. Complete the verification puzzle, then enter the code GitHub emails you.
  4. If GitHub asks about plans or what you'll use it for, the Free plan is all you need. You can skip the questions.
  5. Verify your email address if GitHub asks. Without it you can't create a repository later.
  6. Recommended: turn on two-factor authentication in Settings → Password and authentication.

1D · Sign in to GitHub inside VS Code

This connects VS Code to your GitHub account, so it can save your code there later and so Copilot can work.

  1. In VS Code, click the Accounts icon (the person at the bottom of the left bar).
  2. Choose Sign in with GitHub. It may read Sign in with GitHub to use GitHub Copilot; that's the same thing.
  3. Your browser opens GitHub. Sign in if asked, then click Continue or Authorize Visual Studio Code.
  4. The browser asks to open VS Code. Click Open Visual Studio Code (tick "always allow" if offered).
  5. Back in VS Code, click Accounts again. Your GitHub username now shows there.
Later, when your code goes to GitHub

VS Code may pop up "The extension 'GitHub' wants to sign in using GitHub" or open your browser to approve. That's expected: click Allow and approve.

Permissions: read, then allow

Your assistant asks before it edits a file or runs a command. Read what it wants to do, then allow it. Until your project runs (Part 3), approve one action at a time. Never approve something that deletes files unless you've read it and understand why.

1H · Three tests. Do all three.

Each test proves a different ability. If one fails, fix it before moving on: the rest of the guide depends on all three.

Test 1

It can see your files

Hello, can you see my files? List what's in this folder.

Pass: it lists the files, or says the folder is empty.
Fail: it says it can't access files. You're in a browser chat, or in Ask or Chat mode.

Test 2

It can run a command

Run git --version and node --version in the terminal and tell me the results. Don't install anything yet.

Pass: it asks permission, runs them, and reports a version or "not found". Either answer passes: the point is that it ran a command. The answer helps in Part 3.

Test 3

It can edit a file

Create a file called test.txt containing "it works".

Pass: test.txt appears in the Explorer on the left. Delete it afterwards (right-click → Delete).

Common mistakes to avoid
  • Using chatgpt.com or claude.ai in the browser instead of the assistant inside VS Code. The browser chat can't see or change your files, so every step turns into copying and pasting.
  • Copilot left in Ask mode. It answers questions but can't edit or run anything. Switch to Agent.
  • Two different GitHub accounts. Copilot Pro bought on one account while VS Code is signed in with another. Check the username under Accounts.
  • A free plan that runs out halfway. Upgrade before you start Part 3.
  • The wrong folder open. From Part 3 on, the folder must be my-portfolio, the one that contains package.json.
  • Pasting only the last line of an error. Paste all of it (see Part 2).
  • Letting it delete package-lock.json or run npm audit fix --force. Both break the project.
  • Thinking your assistant subscription pays for your website's AI tools. It doesn't; that's the API key in Part 6.
✓ Check before you move onVS Code is installed. Accounts shows your GitHub username. Your assistant is on a paid plan, and all three tests pass.
Part 2 · 10 minutes · Read once, come back any time

When things break

Errors will happen, even to experienced engineers. This is how you and your assistant fix them together. Every part links back here.

1Copy the whole errorFrom the terminal or the browser, not just the last line. Select the text and copy it, or take a screenshot of a browser error.
2Paste it to your assistantSay what you ran and what you expected.
3Let it fix the causeRead what it changed.
4Run the check againMove on only when it passes.

The "I'm stuck" prompt

I'm following the portfolio guide, Part [N]: [step].
I ran / clicked: [what you did]
I expected: [what should have happened]
I got this (full error below):
[paste everything]
Explain the cause in one plain sentence, fix the cause (not the symptom), run the check again, and tell me what you changed. Don't delete package-lock.json, skip or delete tests, remove the login, or print my secrets.

Same error three times? Stop. Ask it to summarize what it tried, start a new chat, and paste that summary in. Or ask it to undo back to your last saved commit.

Never let it…

  • Delete package-lock.json or use --force fixes
  • Remove checks or tests to make errors disappear
  • Skip or bypass the login "to finish faster"
  • Put API keys in browser code, or print or commit .env.local
  • Start a new app or rewrite everything
  • Show sample or fake results when the AI call fails
  • Say "done" without running npm run preflight
  • Push to the instructor's repository, or force-push
Tip: ask for plain English

Add this line to the end of any prompt: "Then explain what you changed in plain English for someone who doesn't code, and tell me exactly what to click to check it."

Part 3 · 20 to 40 minutes

Get the project running

Your assistant installs Git and Node.js if needed, downloads the class project and starts the sample website on your laptop.

Step 1 · Download the project

In VS Code, open your projects folder (File → Open Folder). Paste this into your assistant:

I'm setting up my laptop for a class. Please do this step by step:
1. Check whether Git is installed. If it isn't, install it for me
   if you can; otherwise tell me exactly how, and wait until I confirm.
2. Check that Git knows my name and email (git config --global
   user.name and user.email). If either is missing, ask me for
   them and set them.
3. Clone https://github.com/nahidfar/claude-master-class.git
   into a new folder called my-portfolio here.
Stop when the clone is done and tell me the full path of my-portfolio.

Then open the new folder: File → Open Folder → my-portfolio. You should see package.json in the Explorer on the left. From now on, always open this folder.

Step 2 · Install and start the website

In the my-portfolio window, paste this:

This is my class project. Please get it running:
1. Check that Node.js 22.18 or newer and npm are installed. If not,
   install Node.js LTS for me if you can; otherwise tell me exactly
   how, and wait until I confirm.
2. Run npm ci, then npm run preflight.
3. Start npm run dev and give me the local URL.
If a step fails, show me the error, explain it in one line,
fix it, and run the step again. Don't delete package-lock.json
or run npm audit fix --force. Finish with a short summary of
what passed and anything I still need to do.

This takes a few minutes. npm run preflight runs the project's checks, and npm run dev keeps running on purpose: it's your site, live on your laptop.

✓ Check before you move onThe sample portfolio for "Alex Morgan" opens at http://localhost:3000, and preflight finished with no errors. Login and the AI tools showing "not implemented" (501) is expected: you build those in Parts 5 to 9.
How to stop and restart the website

The site runs in a terminal at the bottom of VS Code. To stop it, click in that terminal and press Ctrl+C. To start it again, type npm run dev and press Enter. Restart it whenever the guide says so, for example after you change .env.local.

Coming back another day? Open the my-portfolio folder and run npm run dev. No need to install again.

What's happening, and the by-hand way
  • Git downloads ("clones") the project. Node.js runs it; npm comes with Node and installs the building blocks the project needs.
  • npm ci installs the exact versions listed in package-lock.json. It does not install npm itself.

Installing Git: on a Mac, the first time anything uses Git, macOS may offer to install the "command line developer tools". Click Install and wait for it to finish. On Windows, the Git installer's default options are fine.

By hand: install Git and Node.js LTS (22.18 or newer), reopen VS Code, open Terminal → New Terminal, and run each line:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git clone --branch main https://github.com/nahidfar/claude-master-class.git my-portfolio
cd my-portfolio
node --version
npm ci
npm run preflight
npm run dev

Windows: if PowerShell blocks npm.ps1, type npm.cmd instead of npm. Already cloned before? Run git pull to get the latest version.

What's happening

Hiding a button isn't protection: someone could still open the page's address directly. So the check happens on the server. Reference

Words you'll see

VS Code
A free app from Microsoft for working on code. You build your site inside it.
Extension
An add-on for VS Code. Your coding assistant is installed as one.
Command Palette
VS Code's search box for every command: Cmd+Shift+P on a Mac, Ctrl+Shift+P on Windows.
Terminal
A text window where you type commands to your computer. VS Code has one at the bottom.
Repository (repo)
A project folder whose history Git keeps track of.
Git and GitHub
Git tracks changes on your laptop; GitHub keeps a copy online.
Clone
Download your own copy of a repository.
Node.js and npm
Node.js runs the website; npm installs the building blocks it needs.
package-lock.json
The exact list of those building blocks. Never delete it.
localhost:3000
Your website running only on your laptop, for you to see.
npm run dev
Starts that local website and keeps it running until you press Ctrl+C.
.env.local
A private settings file for your password and API key. It stays on your laptop and never goes to GitHub.
API key
A password that lets your website use an AI model and spend your credit.
Commit and push
A commit saves a snapshot on your laptop; a push uploads it to GitHub.
Deploy
Put your website online at a public link.
